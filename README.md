## 📌 AI 프로젝트 요약

- 🧠 **AI 평가 함수**: Stockfish로 라벨링한 30,000 기보를 지도학습하여 **기물 × 포지션 가중치 테이블** 학습
- 🔍 **탐색 알고리즘**: BFS · 강화된 BFS · Minimax · Minimax + Alpha-Beta 4종을 직접 구현·비교
- 📈 **성능 향상**: 기본 BFS(레이팅 400) → 학습 평가함수 + Alpha-Beta(레이팅 **1,850**), 탐색 노드 수 **67% 감소**, 속도 **3배 향상**
- 🧪 **데이터 사이언스 인사이트**: 학습 데이터 양에 따른 정확도 곡선 분석으로 **과적합 임계점(20k 샘플)** 발견
- ⚙️ **시스템**: Pygame GUI + C++ 엔진(pybind11) + Lichess 봇 + Polyglot 오프닝 북

## 1. 연구 배경 및 목적

체스는 3,000개가 넘는 오프닝과 차례당 20가지 이상의 경우의 수로, 오래전부터 인공지능 탐구의 대표적인 주제로 다루어져 왔습니다.
본 프로젝트는 단순한 게임 구현을 넘어, **휴리스틱 탐색과 지도학습 기반 AI 평가 함수**가 실제로 어떻게 결합되고 성능에 영향을 주는지를 직접 검증하는 것을 목표로 합니다.

- 체스 AI에 효율적인 휴리스틱 알고리즘 적용
- 알고리즘별 AI를 **데이터로 학습**시켜 정량적으로 성능 비교
- 가장 성능이 좋은 AI 모델 도출 및 학습 메커니즘 분석

## 2. AI 시스템 개요

```
   [보드 상태]
       │
       ▼
┌──────────────────┐
│  평가 함수 (AI)   │  ◀── 학습된 포지션 가중치 (Stockfish 지도학습)
│  - 기물 가치      │
│  - 포지션 가중치  │
└──────────────────┘
       │
       ▼
┌──────────────────┐
│ 탐색 알고리즘     │  ◀── Minimax + Alpha-Beta Pruning
│ (게임 트리 탐색)  │
└──────────────────┘
       │
       ▼
   [최적 수 선택]
```

AI의 두 축은 **(1) 학습된 평가 함수**와 **(2) 탐색 알고리즘**입니다. 같은 탐색 알고리즘이라도 평가 함수의 품질에 따라 레이팅이 크게 갈리며, 본 프로젝트는 두 축을 모두 정량적으로 검증합니다.

---

## 3. 탐색 알고리즘 구현

| # | 알고리즘 | 설명 |
|---|---|---|
| 1 | **BFS** | 시작 정점에서 가까운 정점부터 탐색. `총 합계 가중치 / 총 노드 수`가 가장 큰 노드를 선택 |
| 2 | **강화된 BFS** | 기물 가중치 기반 가지치기 + 랜덤 함수를 활용한 속도 향상 |
| 3 | **Minimax** | 짝수 깊이(자기 차례)에서 최댓값, 홀수 깊이(상대 차례)에서 최솟값을 선택하는 2인 게임 표준 알고리즘 |
| 4 | **Minimax + Alpha-Beta Pruning** | Minimax 탐색에서 최종 선택에 영향을 주지 않는 가지를 잘라내어 연산량 절감 |

> 시간복잡도는 모두 O(N^D)이지만, Alpha-Beta는 최적 수를 빨리 찾은 경우 가지치기가 활발히 일어나 실측 연산량이 크게 줄어듭니다.

---

## 4. AI 학습 파이프라인 (지도학습)

탐색 알고리즘이 호출하는 **평가 함수**의 핵심인 *포지션별 가중치*를 지도학습으로 학습합니다.

| 단계 | 내용 |
|---|---|
| **1. 데이터 수집** | chess.com에서 Garry Kasparov, Magnus Carlsen 등 그랜드마스터의 PGN 기보 **30,000건** 수집 |
| **2. 라벨링** | Stockfish에 보드 상태를 입력하여 **승패 가중치(평가 점수)** 산출 → 라벨로 사용 |
| **3. 학습** | 각 기물(P/N/B/R/Q/K) × 보드 좌표(8×8)별로 라벨 평균을 산출하여 가중치 테이블 학습 |
| **4. 검증** | Stockfish 모듈 및 Chess.com Komodo25(3200)와의 모의 경기로 정확도·예상 레이팅 측정 |

> 평가 함수 = `Σ(기물 가치) + Σ(학습된 포지션 가중치)` 구조로, 탐색 노드마다 평가됩니다.

## 5. 성능 분석 결과

### 5.1 알고리즘별 성능 비교 (Depth 4)

|  | BFS | BFS + 가지치기 | Minimax | Minimax + Alpha-Beta |
|---|---|---|---|---|
| 탐색 노드 수 | 197,742 | 173,592 | 197,742 | **64,140** |
| 소요 시간 (초) | 21 | 19 | 21 | **7** |
| 정확도 (%) | 56.7 | 61.7 | 68.8 | **70.3** |
| 예상 레이팅 | 400 | 450 | 1,750 | **1,850** |

> 예상 레이팅은 Chess.com Komodo25(3200)와의 경기 후 Chess.com 리뷰 기능을 통해 산출했습니다.

### 5.2 학습 데이터 양에 따른 성능 (Minimax + Alpha-Beta, Depth 4)

| PGN 학습량 | 100 | 1,000 | 10,000 | 20,000 | 30,000 |
|---|---|---|---|---|---|
| 정확도 (%) | 62.2 | 65.8 | 69.2 | **70.3** | 69.9 |
| 레이팅 | 1,100 | 1,300 | 1,800 | **1,850** | 1,800 |

> **AI 인사이트**: 데이터가 늘수록 정확도가 비례 증가하다가 10,000개에서 증가폭이 둔화되고, 30,000개에서는 오히려 미세하게 하락 — **과적합의 전형적 신호**.

### 5.3 학습된 포지션 가중치의 정성적 해석

학습 결과는 사람이 직관적으로 이해할 수 있는 체스 이론과 잘 부합했습니다.

- **폰**: 승진 직전(7/8라인, 1/2라인)에서 가장 높은 가중치
- **나이트**: 중앙 및 c3/c6/f3/f6 — 클래식한 *나이트 발전 자리*에서 높음
- **비숍**: 색에 관계없이 중앙일수록 높음
- **룩, 퀸**: 중앙이 다소 높음

## 6. AI 관점 핵심 성과

- 🎯 **학습된 평가 함수**가 정확도를 56.7% → 70.3%로 크게 끌어올림 (탐색 알고리즘만 바꿔서는 한계가 있음을 검증)
- ⚡ **Alpha-Beta Pruning** 적용으로 같은 탐색 깊이에서 노드 67% 감소, 속도 3배
- 📊 **데이터 양 vs. 성능 곡선** 분석을 통해 과적합 임계점(20k 샘플)을 실험적으로 도출
- 🧠 학습된 가중치 분포가 **사람이 알고 있는 체스 이론과 일치** — 학습이 의미 있는 표현(representation)을 획득했음을 시사

## 8. 실행 방법

### 요구 사항
- Python 3.12+
- pygame
- pybind11 (C++ 엔진 빌드용)
- C++20을 지원하는 컴파일러 (MSVC, GCC, Clang)

### C++ 엔진 빌드 (선택)

탐색 성능을 위해 C++ 엔진을 빌드해서 사용하는 것을 권장합니다.

```bash
# Windows
build.bat

# macOS / Linux
python setup.py build_ext --inplace
```

빌드된 `chess_cpp.*.pyd` (또는 `.so`) 파일이 main.py에서 자동으로 로드됩니다. 빌드 실패 시 Python 구현 (`engine.py`, `chessAi.py`)으로 자동 폴백됩니다.

### 게임 실행

```bash
python main.py
```

> **참고**: 오프닝 북 데이터 `book.bin`(약 170MB)은 GitHub의 100MB 파일 제한으로 저장소에서 제외되어 있습니다. 오프닝 북 기능을 사용하려면 [Polyglot 형식의 체스 오프닝 북](https://github.com/lichess-org/chess-openings)을 별도로 다운로드하여 프로젝트 루트에 `book.bin`으로 배치해 주세요.

### Lichess 봇 실행

```bash
python lichess_bot_engine.py
```

## 9. 향후 개선 방향

본 프로젝트는 **휴리스틱 + 지도학습 기반 평가 함수**까지 다루었으며, 다음 단계로 다음 AI 트랙을 계획하고 있습니다.

- 🧠 **신경망 기반 평가 함수**: 보드 상태를 입력으로 받는 CNN/Transformer 기반 평가 모델 (NNUE 스타일 포함)
- 🔁 **강화학습 / 셀프 플레이**: AlphaZero 계열의 MCTS + Self-play로 학습 데이터 의존성 제거
- 🧩 **평가 요소 다양화**: 공격 가능 위치 수, 오프닝/미들게임/엔드게임별 포지션 가중치 분리, 킹 안전성 등
- 📊 **하이퍼파라미터 탐색**: 탐색 깊이 × 평가 함수 복잡도 × 학습 데이터 양의 trade-off 정량 분석
